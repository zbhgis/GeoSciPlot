说明

· 上传的图片会立即写入 raw/；点发布后才会压缩出缩略图、更新索引并生成站点。
· 添加图片有三种方式：拖拽、点击选择、Ctrl+V 粘贴。 粘贴支持混合内容：自动只提取其中的图片，文本忽略； 截图 / 复制的图片文件 / 网页选区里的 <img>（含多张）都能进来， 远程图片由本机服务代取，单次上限 30 张。 扩展名以剪贴板 MIME 为准；浏览器合成的占位名（image.png / blob 等）会自动改成 paste-时间戳.ext。从磁盘拖进来的文件即使叫 image.png 也保留原名。 在输入框里粘贴表格/文本时不会抢成图片。
· 标准导入：剪贴板里是「编号 DOI 列表 + 按顺序的图」时 （如 1. https://doi.org/… 共 N 行，下面跟 N 张图）， 点按钮或直接 Ctrl+V，都会把 DOI 与图按顺序一一配对并自动预填； 编号行里的 重复 DOI（同一篇论文多张图）按位置照常配对，不会跳过； 数量对不上会明确提示，不会静默丢弃。
· raw/ 是收件箱兼原图留存：图发布后仍留在里面（在「raw 暂存区」里标记为「已发布副本」）； 逐字节原图另存于 images/full/，所以清空 raw/ 不会损坏图库，但未发布的图会丢。
· 图片 id 由内容算出（sha1 前 10 位），与文件名无关 —— 重复上传同一张图会被识别出来。
· 填 DOI 时会实时查重：若该 DOI 已被图库或本次待发布里的图用过， 会在输入框下方列出同 DOI 的图片 id（DOI 大小写不敏感）。 这只是提示、不阻断发布 —— 同一篇论文配多张图是正常情况。
· 若上传后不发布，图片仍留在 raw/，下次生成会以「未命名」收录，可在 meta/titles.csv 里补。
· 批量修改的正确姿势：图片管理页里每条「暂存保存」都是纯本地写（毫秒级）， 连续改多少条都不用等；改完点「一键推送全部」，把所有暂存过的变更 （含 raw/ 里未入库的图、其他图片的改动）一次性构建站点、提交推送并同步服务器。
· 删除图片会同时移除缩略图、原图副本、raw/ 原图与索引条目，并同步 GitHub。
· 保存并推送 = 暂存 + 一键推送：写 meta/titles.csv → prepare.py → build_site.py → git add/commit/push →（可选）同步服务器。
· 制图经验页签管理 content/guide/*.md（mystation 同款交互）：列表默认只读，点某行「编辑」解锁该行改元数据 （标题 / 日期 / 两级标签，改日期会同步重命名文件的日期前缀——构建排序与 slug 以文件名前缀为准）， 「正文」打开浮层编辑器只改正文（frontmatter 原样保留，保存前自动备份 .bak，带 mtime 冲突检测防并发覆盖）； 「新建文章」自动生成 frontmatter 与 日期-slug.md 文件名；「删除」把 md 移入 content/.trash/guide/（本机回收站，git 不跟踪）可恢复。 文章改动都只写本地文件，点「推送文章改动」才构建站点并发布。
